# 通用接口 GPU 实测

日期：2026-10-23。显卡 RTX 5060 Ti 16GB；使用已有 GPT-SoVITS 的 Python 3.9.13 / PyTorch 2.7.0+cu128 环境，未重装运行环境。

测试模型为前次下载并校验的官方 GPT-SoVITS v5turbo、v5dev。使用同一份现有参考音频及原文；通过通用 `custom-http` JSON 模板连接官方 `/tts`，没有增加逐模型 Provider。服务仅监听 loopback，关闭流式，turbo 4 步、dev 32 步。真实音频文件及数值记录保存在工作区的交付目录，未打包入插件。

## 已通过

- v5turbo 和 v5dev 在 CUDA 上加载并合成；输出 48kHz 单声道 WAV。
- turbo 的已保存短句为 3.24 秒、3.44 秒，停止后恢复样本为 2.84 秒，均检查到非零波形。
- 预热后成功短句请求记录约 1.44 秒、2.43 秒；首轮初始化包括语言资源、CUDA graph 准备，曾耗时约 68 秒。耗时随缓存、模型和输入变化，不是实时性能保证。
- v5dev 32 步测试请求约 12.23 秒，返回 334124 字节。
- 请求取消在约 52 毫秒返回 CANCELLED，立即发起下一次合成成功；该恢复请求耗时约 5.87 秒，包含等待上一个 GPU 计算完成的时间。停止不等于立即中止 GPU kernel。
- 独立源码浏览器验收页：三句逐段合成播放、暂停/继续、停止后重新朗读。共解码 6 段，观察到两次正常播放完成；中途停止的任务不计为正常完成。

## 运行环境问题及处理

1. 便携 Python 的 `_pth` 不自动包含新项目根目录。测试启动器显式设置新源码与 `GPT_SoVITS` 路径，复用已有 ffmpeg/NLTK 资源。
2. 新项目缺少 fast-langdetect 的 `lid.176.bin`，上游首次请求自动下载并拖慢测试。终止后保留了不完整文件，并从已有安装复用完整模型，避免重复下载。
3. 上游 API 顶层创建 asyncio.Lock，Python 3.9 在构造时绑定事件循环，而 uvicorn.run 又新建循环。首次真正重叠请求触发“Future attached to a different loop”。仅在本地测试启动器中让 API 初始化与 uvicorn serving 使用同一个循环，重测取消/立即重试通过。插件 HTTP 传输无需为此新增模型专属逻辑。

这些是本地旧环境的复用措施，不代表官方支持矩阵已扩大。新安装仍应遵守上游当前 Python 和依赖要求。

## 验证边界

首轮浏览器使用真实设置控制器、Host 路由、队列与 Web Audio，宿主外壳为隔离验收页。随后追加了下述正式部署验收。波形检查和浏览器播放状态不能代替人耳对音色相似度、漏字、发音和自然度的评价。其他模型协议的覆盖情况仍以通用接口模拟测试及逐模型实测记录区分。
